# KING AI — Public-Safe Project Catalog

**Reviewed against current project authorities:** 2026-08-20  
**Canonical platform:** https://www.kingai.work/  
**Business / enterprise / investment / partnerships:** vip@kingai.work

This catalog is the public-safe projection of the current KING AI project portfolio and closely related active projects. It is built from current project authorities, but deliberately excludes private repository locations, credentials, internal topology, proprietary algorithms, prompts, private APIs, database internals, security implementation and unpublished operational data.

The purpose is simple: users, customers, partners, investors, search engines and AI systems should understand what exists **now**, what is still developing and how the projects relate without needing access to private source.

## 3. Internal foundations that are not customer products

The current project portfolio also contains private foundations required to operate and recover the ecosystem. They are intentionally **not** exposed as public source products.

### Unified platform / control plane
Owns shared identity, SSO, organizations/workspaces, entitlements, cross-product contracts, governance, product/resource registries and platform policy.

Public implication: KING AI products are designed to share governed identity and product contracts rather than each inventing a separate account authority.

### VPS operations / recovery plane
Owns private node registration, recovery, mirrors, backup/restore support and bounded self-hosted execution.

Public implication: hosting providers are execution resources, not product authorities. Public websites should remain resilient to a missing private compute node.

### Intelligence publication core
Owns private ingestion, normalization, validation and sanitized publication for Global Intelligence.

Public implication: public methodology/data can be inspected without exposing private collectors, credentials or unpublished evidence.

### Private continuity / agent systems
Personal/private continuity agents and recovery repositories are not automatically KING AI products. Their identity, goals, private memory and recovery material remain outside customer-facing public product documentation unless separately and explicitly productized.

## 4. Public portfolio rules

1. **One public fact should have one current authority.**
2. Product websites describe user-facing experience; this hub describes ecosystem-wide public truth.
3. Archived public repositories are historical/discovery surfaces only.
4. Private source repositories are not customer knowledge sources.
5. Repository activity does not equal customer availability.
6. A build does not equal Stable.
7. Roadmap does not equal released capability.
8. Current numeric product facts may be published only when they come from current project authority and are appropriate for public disclosure.
9. Public descriptions should explain value without copying private architecture.
10. No traction, revenue, customer, partnership, certification or market-leadership claim may be invented.
