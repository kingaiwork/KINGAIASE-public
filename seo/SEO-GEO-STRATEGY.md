# English

## 1. Objective

Make KING AI SEA discoverable as a clear, trustworthy and citable entity across traditional search, AI-generated answers, developer research and future agent-discovery experiences.

The strategy prioritizes entity consistency, useful depth, technical accuracy, crawlability, canonicalization, internal linking, structured data, primary-source evidence and real freshness.

## 2. Entity Architecture

Primary entity:

**KING AI SEA — Intelligent Lifeform Platform**

Secondary capability clusters:

- persistent digital intelligence
- personal second brain
- AI Workforce
- AI Employees
- multi-agent collaboration
- agentic workflows
- intelligent websites / applications
- long-term continuity and memory
- controlled evolution
- enterprise governance
- private / hybrid deployment
- developer ecosystem
- industry intelligence

Do not describe these secondary clusters as competing parent products.

## 3. Search-Intent Architecture

The website should use dedicated canonical pages for major intents, including:

`/intelligent-lifeform/`, `/personal-ai/`, `/enterprise/`, `/ai-workforce/`, `/ai-employees/`, `/control-center/`, `/automation/`, `/memory/`, `/evolution/`, `/website-ai/`, `/app-ai/`, `/integrations/`, `/developers/`, `/industries/`, `/deployment/`, `/trust/`, `/intelligence/`, `/faq/` and `/contact/`.

Chinese equivalents should use `/zh/...` and preserve the same entity graph.

## 4. KING AI Intelligence as Freshness Layer

`/intelligence/` should function as the current research / blog layer.

The research cycle runs every two hours, but publication is selective. The goal is not volume; it is high-value freshness around AI agents, intelligent lifeforms, AI Workforce, memory, durable execution, protocols, governance, evaluation, infrastructure and industry AI.

Each article should have one primary intent and should update an existing canonical article when overlap is high.

## 5. On-Page Standard

Each canonical page should have:

- unique title
- unique meta description
- one clear H1
- direct definition / answer near the top
- descriptive H2/H3 structure
- useful factual examples
- internal links
- canonical URL
- meaningful update date
- relevant structured data
- clear CTA where commercially appropriate

## 6. Technical SEO

Maintain:

- crawlable HTML
- XML sitemap
- robots.txt
- stable canonical URLs
- correct hreflang for multilingual pages
- mobile performance
- image alt text
- descriptive file names
- Open Graph/social metadata
- clean redirects
- no accidental noindex
- no competing duplicate URLs

## 7. Structured Data

Recommended where accurate:

- Organization
- WebSite
- WebPage
- BreadcrumbList
- Article / TechArticle for Intelligence
- SoftwareApplication / Product / Service only where the visible page supports it

FAQPage should only mark up visible FAQ content. Do not treat FAQPage as a guarantee of Google FAQ rich results; current Google display eligibility is very limited for general commercial sites.

## 8. GEO / AI Search

Optimize for accurate retrieval and citation through:

- direct definitions
- concise standalone factual statements
- tables
- canonical terminology
- evidence and first-party technical citations
- explicit product-status wording
- related canonical links
- no unsupported superlatives

Monitor Bing Webmaster Tools AI Performance where available, including citations, cited pages, grounding queries/intents and citation trends.

## 9. Discovery & Freshness

When a website page materially changes:

- update sitemap dates accurately
- submit changed URLs using IndexNow when deployed
- use Google Search Console recrawl tools selectively for important pages
- do not modify dates without substantive content changes

## 10. Content Clusters

Core clusters:

- Intelligent Lifeform
- Personal AI / Second Brain
- AI Workforce / AI Employees
- Agentic AI / Automation
- Memory / Continuity / Controlled Evolution
- Trust / Governance / Evaluation
- Website / App Intelligence
- Developer / Integration / MCP / A2A
- Industry AI
- Private / Hybrid Deployment
- KING AI Intelligence

## 11. GitHub Role

GitHub is a technical-brand and source-of-truth surface, not a duplicate website.

Use:

- README as portal
- `docs/` as canonical public documentation
- `intelligence/` as current research
- `seo/` as search / entity architecture
- `llms.txt` as machine-readable facts
- role / industry packs as structured knowledge sources for website pages

## 12. Quality Over Volume

Do not mass-create thin pages by swapping role, location or industry names. Every indexed website page should represent a genuinely distinct user intent and useful content body.

# 中文

## 1. 总目标

KING AI SEA 的 SEO/GEO 不只是传统排名，而是让 Google、Bing 和 AI Answer Systems 清晰理解：

**KING AI SEA 是一个面向个人与企业的 Intelligent Lifeform Platform / 智慧生命体平台。**

## 2. 实体统一

统一母体只有 KING AI SEA。AI Workforce、AI 员工、个人第二大脑、Website AI、App AI、自动化、行业方案都是同一智慧生命体的能力和应用形态。

## 3. 页面架构

官网按照真正不同的搜索意图建立独立 canonical 页面，并使用 `/zh/...` 提供完整中文版本。英文和中文页面保持同一个实体关系，但不在正文中机械混排。

## 4. KING AI 智慧前沿

`/intelligence/` 作为 Blog / Research / Intelligence 新鲜内容层。系统每两个小时研究一次，但只在有真正新价值时发布；高度相似主题更新已有文章。

## 5. SEO / GEO 核心质量

每个重点页面应有唯一 Title、Description、H1、顶部直接答案、清晰结构、内部链接、canonical、真实更新时间和准确 Structured Data。

GEO 更强调可引用：短定义、事实句、表格、权威一手来源、清晰品牌实体、能力状态和相关权威页面链接。

## 6. 结构化数据

首页优先 Organization / WebSite，内容页使用 WebPage / BreadcrumbList，Intelligence 使用 Article / TechArticle。FAQPage 只描述页面真实 FAQ，不把它宣传成 Google 一定展示 Rich Result。

## 7. 新内容发现

官网发生实质更新后，准确更新 sitemap，并在部署后通过 IndexNow 通知参与搜索引擎；重点页面需要时再使用 Google Search Console 请求重新抓取。

## 8. 衡量

传统 SEO 看索引、曝光、点击、品牌词/非品牌词和转化；GEO 看 AI Citations、Cited Pages、Grounding Queries、品牌实体准确度和 AI 来源流量。

详细执行标准见：[SEO / GEO Quality Standard](SEO-GEO-QUALITY-STANDARD.md)。
