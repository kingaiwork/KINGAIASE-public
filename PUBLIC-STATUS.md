**Last project-authority review:** 2026-08-20  
**Canonical platform:** https://www.kingai.work/

This file prevents roadmap language, repository activity, screenshots or private-development progress from being mistaken for verified customer availability.

## Status vocabulary

### Available / public product surface
A user-facing public surface exists. This does not automatically mean every feature, platform, integration or commercial package is generally available.

### Production Candidate
A product line has reached a production-readiness validation stage, but signing, device, store, lifecycle, operational or other release gates may remain.

### Active working foundation
Substantial current product capability exists, but the product should still be described according to verified current scope rather than assumed feature parity with established competitors.

### Active product direction
The product has a current source/runtime/product authority and active direction. Exact customer availability must still be confirmed.

### In Development
Actively being built. Not a universally finished product claim.

### Pre-Alpha
Early product stage. Product direction may be evaluated, but production expectations must remain conservative.

### Roadmap
Future direction only.

### Legacy public repository
Historical/discovery repository, not a current implementation, installation or release authority.

## Status integrity rules

1. Repository activity is not customer availability.
2. A successful build is not automatically Stable.
3. Production Candidate is not automatically Stable.
4. Roadmap is not released capability.
5. A public website can describe direction, but production scope must still be verified.
6. Historical screenshots/releases/cached pages do not override current status.
7. Numeric product facts should be published only when current project authority supports them and public disclosure is appropriate.
8. Product status must not be inflated for marketing or investment presentation.
9. No user, revenue, customer, partnership, funding, certification, market-share or leadership claim may be invented.

## Core implementation remains private

This guide deliberately omits private repository locations where unnecessary, production source, proprietary algorithms, internal prompts, memory structures, model routing, credentials, private APIs, database internals, private topology, unpublished evidence, sensitive security implementation and confidential customer/operational information.
