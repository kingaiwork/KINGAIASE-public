# 📄 KING AI SEA — Enterprise RFP Template

> Public procurement template for evaluating an intelligent-lifeform and AI Workforce deployment. No proprietary implementation is disclosed.

---

# English

## 1. Organization Profile

- Organization / business unit
- Industry
- Regions
- User count / teams
- Existing systems
- Security / deployment constraints
- Primary business objectives

## 2. Mission Scope

For every requested AI mission define:

| Field | Required Detail |
|---|---|
| Business outcome | What should improve? |
| User / owner | Who owns the mission? |
| Frequency | One-time, recurring, event-driven, continuous |
| Data scope | Approved knowledge and systems |
| Action scope | Read, draft, recommend, execute, approve/escalate |
| Human control | Required approvals / override |
| KPI | How success is measured |
| Risk level | Low / medium / high / restricted |

## 3. Intelligent-Lifeform Requirements

Vendor response should address:

- persistent identity and continuity
- multi-role AI Workforce
- mission coordination
- long-running workflows
- knowledge and data integration
- website/app/voice presence
- human approvals and escalation
- observability and evaluation
- audit history
- private/hybrid deployment options
- lifecycle management
- controlled improvement

## 4. Integration Requirements

List required categories:

- email / calendar
- CRM / ERP / PMS
- CMS / websites / apps
- databases / data warehouses
- file systems / document stores
- cloud / VPS / Linux
- developer systems / GitHub
- communication platforms
- APIs / webhooks / MCP-compatible tools where applicable

For each integration specify read/write scope and approval boundaries.

## 5. Security & Governance Requirements

Request documentation on:

- identity and authentication
- role-based access
- least-privilege design
- approval workflows
- auditability
- human override
- secrets handling approach
- data isolation options
- incident response
- logging and observability
- environment separation
- high-risk operation controls

Do not require disclosure of proprietary security internals that would create additional risk.

## 6. Deployment

Requested model:

- cloud
- dedicated VPS
- private server
- private cloud
- hybrid
- customer-controlled environment

Include networking, access, data residency and operational ownership requirements.

## 7. Evaluation

Require a pilot or staged rollout with:

- baseline
- target metrics
- test scenarios
- approval tests
- failure / recovery tests
- human handoff tests
- security boundary tests
- performance and cost observations
- go/no-go criteria

## 8. Commercial Response

Request:

- implementation scope
- recurring platform / support scope
- integration scope
- custom development scope
- deployment responsibilities
- support model
- change-control approach
- assumptions and exclusions

## 9. Required Status Labels

Every vendor capability should be labeled:

**Available / In Development / Planned / Custom-by-Scope / Not Included**.

# 中文

## 企业 RFP 应包含

### 组织资料
行业、地区、团队规模、现有系统、安全约束、主要业务目标。

### Mission 范围
每个 AI Mission 必须明确：业务结果、负责人、执行频率、数据范围、行动范围、审批、KPI 与风险级别。

### 智慧生命体能力要求
持续身份、长期连续性、多角色 AI Workforce、Mission 协同、长任务、知识连接、网站/APP/语音存在、审批升级、可观测、审计、私有部署、生命周期管理和受控优化。

### 集成要求
邮件、日历、CRM、ERP、PMS、CMS、网站、APP、数据库、文档、Cloud、VPS、Linux、GitHub、通信平台、API、Webhook 和适用的 MCP 工具。每项都必须明确读写和审批范围。

### 安全治理
身份、权限、最小权限、审批、审计、人类接管、密钥管理原则、数据隔离、事件响应、日志、环境隔离与高风险操作控制。

### 部署
Cloud、Dedicated VPS、Private Server、Private Cloud、Hybrid 或客户控制环境。

### 评估
必须进行基线、目标指标、测试场景、审批测试、故障恢复、人工接管、安全边界、成本和 Go/No-Go 验收。

### 商业回复
实施、平台、支持、集成、定制、部署责任、支持模型、变更控制、假设与排除项。

### 状态标签
所有能力统一标注：**已可用 / 开发中 / 规划中 / 按项目范围定制 / 不包含**。
