# ✅ KING AI SEA — Implementation & Acceptance Framework

---

# English

## 1. Discovery Acceptance

Before implementation, confirm:

- mission statement approved
- owner identified
- systems inventoried
- data scope approved
- permissions defined
- risks classified
- KPI baseline available
- deployment model selected

## 2. Build Acceptance

Validate:

- intended roles exist
- knowledge sources are connected correctly
- required integrations work within scope
- read/draft/recommend/execute boundaries are enforced
- approval paths work
- human handoff works
- logs and observability are available
- unsupported actions fail safely or escalate

## 3. Scenario Testing

Test at least:

- normal success case
- ambiguous request
- missing data
- integration unavailable
- denied permission
- required approval
- human takeover
- retry / recovery
- out-of-scope request
- sensitive/high-risk request

## 4. Quality Acceptance

Measure appropriate indicators:

- task success
- answer / action quality
- escalation quality
- completion time
- human review rate
- rework rate
- customer/user satisfaction where applicable
- cost per mission where measurable

## 5. Security Acceptance

Confirm:

- access scope
- role scope
- tool scope
- environment scope
- secret handling
- approval controls
- audit history
- override / stop controls

## 6. Production Readiness

Go-live requires:

- named owner
- support path
- monitoring
- incident path
- backup / rollback as relevant
- change-control process
- known limitations documented
- capability status accurately labeled

## 7. Expansion Gate

Do not expand autonomy merely because a pilot is successful. Expand only when quality, governance, observability and business value remain acceptable at the next scope.

# 中文

正式验收分为七层：

1. **Discovery** — Mission、负责人、系统、数据、权限、风险、KPI、部署均确认。
2. **Build** — 角色、知识、集成、权限等级、审批、人类接管、日志、拒绝/升级均可用。
3. **场景测试** — 成功、歧义、缺数据、集成故障、权限拒绝、审批、人工接管、恢复、越界和高风险场景全部覆盖。
4. **质量** — 成功率、质量、升级质量、完成时间、人工审查、返工、满意度、成本。
5. **安全** — 访问、角色、工具、环境、密钥、审批、审计、停止/接管。
6. **生产就绪** — 有负责人、支持、监控、事件路径、回滚、变更管理和已知限制。
7. **扩展门槛** — Pilot 成功不代表自动扩大自主权，必须在下一层范围继续满足质量、治理、可观测和商业价值要求。
