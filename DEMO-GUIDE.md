# KING AI — Public Demo & Evaluation Guide

This guide helps a new user, buyer, partner or investor evaluate KING AI through public surfaces without needing access to private production systems.

## Fastest evaluation path

### 10 minutes — understand the portfolio
1. Open https://www.kingai.work/
2. Read `START-HERE.md`.
3. Review `PRODUCTS.md` and `PUBLIC-STATUS.md`.
4. Choose one product that matches a real need.

Do not evaluate the ecosystem only by counting product names. Start with independent usefulness.

### 30 minutes — test user value
Choose one of these paths:

**Productivity**  
Explore Online Tools or the current Office product surface and ask: can a normal user obtain value without learning internal architecture?

**Infrastructure**  
Review OPS positioning and ask: are operational actions understandable, bounded and recoverable?

**Security**  
Review the current Security public surface at https://aq.kingai.work/ and distinguish candidate/released status from roadmap.

**Global intelligence**  
Open https://intel.kingai.work/, compare countries, inspect methodology, sources and evidence coverage, and ask whether uncertainty is understandable.

**Persistent consumer experience**  
Explore AI Life or KINGAI Pet and evaluate whether progress, history and reasons to return feel meaningful.

### 60 minutes — evaluate the business
Read:
- `BUSINESS.md`
- `INVESTORS.md`
- `MARKET.md`
- `COMMERCIAL-PACKAGING.md`
- `COMPETITIVE-POSITIONING.md`
- `PUBLIC-METRICS.md`

Then answer:
- Which product has the clearest immediate value?
- Which product can become high-frequency?
- Which product can support a paid relationship?
- Which product can create efficient acquisition?
- Which cross-product path is natural rather than forced?

## Enterprise pilot evaluation

A serious enterprise evaluation should select one bounded workflow and define:
- current baseline;
- authorized data;
- allowed actions;
- human approvals;
- escalation path;
- success metric;
- rollback/recovery expectations;
- pilot duration and decision point.

Examples of useful success metrics include response time, workflow completion, operator hours saved, lead capture, research time saved or incident-handling improvement. Exact metrics depend on the product.

## Investor evaluation

An investor should review three layers separately:

### Product proof
Does at least one product solve a meaningful problem and create return behavior?

### Portfolio logic
Do discovery, frequency, trust, action, insight and continuity create plausible expansion paths?

### Execution quality
Does the team distinguish current truth from roadmap, protect core technology, reduce duplicated systems and measure what matters?

See `DILIGENCE.md` for a deeper checklist.

## What is not a valid proof point

Do not treat the following as proof of commercial maturity by themselves:
- repository count;
- commit count;
- an AI-generated page;
- a passing build;
- roadmap language;
- a concept screenshot;
- a private implementation existing somewhere;
- a model being technically capable of an action.

Commercial proof requires user value, availability, reliability and appropriate governance.

## Public/private boundary

A public demo should prove the user experience and product thesis. It should not expose production credentials, internal topology, proprietary algorithms, private APIs, internal prompts, sensitive security controls or confidential datasets.
